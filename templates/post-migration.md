> Матеріал знеособлено: без секретів, реальних доменів і внутрішніх ідентифікаторів.

## Вихідний стан

Що було до міграції:
- архітектура/конфіг;
- обмеження;
- поточні болі.

## Чому потрібна міграція

Бізнесові або технічні причини:
- масштабування;
- надійність;
- безпека;
- вартість підтримки.

## Цільовий стан

Що має бути після завершення:
- цільова архітектура;
- ключові критерії успіху.

## План міграції по етапах

1. Підготовка.
2. Пілот.
3. Частковий перенос.
4. Повний перенос.
5. Стабілізація.

## Backout plan

Що робиш, якщо щось йде не так:
- умови відкату;
- кроки відкату;
- як перевіряєш відновлення.

## Реалізація

Що реально виконано на кожному етапі.

```bash
# приклад команд
helm upgrade --install ...
kubectl rollout status deploy/...
```

## Результат і метрики

Порівняння до/після:
- продуктивність;
- стабільність;
- операційне навантаження.

## Технічний борг і наступні кроки

Що залишилось доробити після основної міграції.
