# Paparoot

Практичний DevOps-блог на GitHub Pages. Тут збираються короткі технічні статті, розбори змін в існуючих системах, базові пояснення для інженерів, які ростуть у професії, і нотатки з тем, що регулярно спливають у реальній роботі та на співбесідах.

## Про що цей репозиторій

Це не просто статичний сайт, а робочий репозиторій для публікацій. Основна ідея блогу проста: менше переказу документації, більше конкретики, інженерної логіки і зрозумілого контексту.

Основні теми:

- `Kubernetes`
- `Terraform`
- `CI/CD`
- `Observability`
- Linux, networking, troubleshooting

## Що вже є в блозі

- кастомна головна сторінка у форматі стрічки
- окрема сторінка `Про блог`
- єдиний layout для сторінок і постів
- швидкий пошук по заголовках, прев'ю і тегах
- шаблони для нових технічних статей
- підтримка рубрик і серій для тематичних циклів

## Формати статей

### `change-case`

Для кейсів, де система вже існує і потрібно внести точкову зміну без фантазій про greenfield.

Шаблон:

- `templates/post-existing-system.md`

### `migration`

Для міграцій, рефакторингів, поетапних переносів або переробок, де важливі послідовність, ризики і контроль змін.

Шаблон:

- `templates/post-migration.md`

### `basic-topic`

Для простих пояснювальних постів, коли треба розкласти базову тему без зайвої академічності.

Шаблон:

- `templates/post-basic-topic.md`

## Рубрики і серії

Для великих тем з кількома постами можна використовувати таку схему у front matter:

```yaml
categories: [devops, basics]
rubric: "DevOps база - back to the core"
rubric_key: basics
series: "devops-basics"
series_title: "База без магії"
series_part: 1
```

- `rubric` це видима рубрика на сайті
- `rubric_key` це стабільний ключ для опису і сторінки рубрики
- `series` це технічний ідентифікатор серії
- `series_title` це людська назва серії
- `series_part` це порядок поста всередині серії

Опис рубрик зберігається в `_data/rubrics.yml`, а сторінки рубрик створюються окремими файлами в `rubrics/`.

## Як додати нову статтю

1. Обери шаблон у `templates/`.
2. Створи файл у `_posts/` у форматі `YYYY-MM-DD-slug.md`.
3. Заповни front matter:
   - `title`
   - `date`
   - `categories`
   - `rubric` якщо це окрема рубрика
   - `rubric_key` якщо в рубрики є власна сторінка й опис
   - `series`, `series_title`, `series_part` якщо це серія
   - `tags`
   - `featured`
   - `case_type`
4. Напиши текст у практичному форматі: контекст, проблема, рішення, перевірка результату, висновки.
5. Якщо є скріншоти, складай їх у `assets/img/posts/<post-slug>/`.

## Публікаційні правила

- Не публікувати секрети, токени, паролі або приватні ключі.
- Не світити реальні домени, внутрішні URL, репозиторії, ідентифікатори чи робочі IP.
- Для прикладів використовувати знеособлені дані.
- Не перетворювати статті на рекламні тексти або перекази документації.
