> Эта статья намеренно обезличена: без secrets, реальных доменов, имен кластеров и внутренних идентификаторов.

## Проблема

В test/sandbox-окружении сканер уязвимостей работал нестабильно:
- периодически появлялись пропуски в результатах сканирования;
- часть задач завершалась с таймаутом;
- отчетность приходила неравномерно после деплоя.

Цель: получить предсказуемый и повторяемый цикл сканирования без избыточной нагрузки на кластер.

## Диагностика

Что проверял в первую очередь:

```bash
kubectl get pods -n security
kubectl get events -n security --sort-by=.lastTimestamp
kubectl logs deploy/trivy-operator -n security --tail=200
kubectl top nodes
```

Наблюдения:
- всплески ошибок совпадали с периодами высокой нагрузки;
- часть job-сканов стартовала одновременно и конкурировала за ресурсы;
- настройки по умолчанию оказались слишком агрессивными для sandbox.

## Решение

В values-конфигурации применил консервативный профиль для sandbox:
- ограничил параллелизм сканирования;
- выставил явные requests/limits;
- включил более предсказуемое расписание/ритм сканов;
- сократил набор сканируемых сущностей до приоритетных.

Пример подхода (обезличенный):

```yaml
operator:
  scanJobsConcurrentLimit: 2

resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    cpu: 500m
    memory: 512Mi

scan:
  skipNonCriticalNamespaces: true
  retryBackoff: "30s"
```

## Проверка результата

После изменений проверял:
- стабильность подов оператора в течение нескольких циклов;
- отсутствие волны таймаутов у scan jobs;
- равномерное появление отчетов после релизов.

Контрольные команды:

```bash
kubectl get pods -n security -w
kubectl get jobs -n security
kubectl logs deploy/trivy-operator -n security --since=30m
```

Итог теста:
- количество сбоев заметно снизилось;
- поведение стало предсказуемым для sandbox;
- стало проще планировать дальнейшее ужесточение политики сканирования.

## Что дальше

Следующие итерации для production-подхода:
- развести профили настроек по окружениям;
- добавить алерты на деградацию сканирования;
- зафиксировать SLO по времени публикации результатов.
